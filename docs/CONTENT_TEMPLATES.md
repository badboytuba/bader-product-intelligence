# Category-specific description models — 16.0.1.7.0

This feature is delivered to **QAS only**. Runtime certification is recorded
separately; this document is not proof of deployment or live provider validation.

## Operator workflow

Open **Producto Intelligence → Modelos de descripción** to create, duplicate or
edit reusable editorial instructions. Templates contain independent short/long
instructions, optional word-count targets and either a free layout or the
two-section layout. Administrative rights are required.

In **Descripciones y FAQs → Nancy AI Studio**, **Automático** resolves the model
from the product's **internal Odoo category**, following its nearest configured
ancestor and finally **General Bader**. This is not an eCommerce category or niche.
The selector explains the effective model, revision and source. Choosing another
model creates a product-specific draft exception. **Guardar sección** or
**Guardar ficha** persists that exception together with the content; saving
Automático removes it. Selection alone does not generate, save or publish text.

Generation uses **saved Odoo product information**, not unsaved name/category
edits. Review the proposal before saving. Edits made while requests are running
remain drafts. A response for an obsolete product/model/revision cannot replace
the current text. No automatic paid retry occurs after an invalid proposal.

## Initial models

- **General Bader** retains the existing 45–70 word commercial summary and
  350–650 word expanded-description targets.
- **Instrumental Bader** targets 45–70 words for the summary, with no imposed
  minimum for the expanded text. It contains exactly two paragraphs below
  `Descripción General`, followed by `Especificaciones Técnicas`. Technical
  bullets are rendered from confirmed saved facts rather than fabricated values.
  When no specifications exist, the output explicitly indicates pending
  verification. Word targets are guidance, not a reason for an automatic retry.

The attached editorial reference is not evidence of surgical steel, autoclave
compatibility, biocompatibility, certifications or guarantees. Prior AI prose is
not technical evidence. Values require known units; variant/Pack-specific facts
must not be generalized to all variants. Product names are preserved. The long
HTML does not repeat the product heading already supplied by the website.

QAS rollout explicitly associates Instrumental with the verified internal roots
Clínica/Instrumental, Clínica/Cirugía/Instrumental para implantes,
Laboratorio/Instrumental and Odontología/Instrumental. Descendants inherit.
Database IDs are environment-specific and are not portable seed data. Existing
products are never reclassified or regenerated by installation or upgrade.

## Compatibility and administration

The new `bpi.content.template` model supplies category defaults and optional
product overrides. Library data is administrator-managed shared configuration;
product access continues to respect company context and record permissions.
Templates referenced by categories/products cannot be archived or deleted until
their references are replaced. The General fallback is protected. Seed data is
not reapplied over administrator customizations during subsequent upgrades.

Existing generation response fields and save routes remain compatible.
`contentTemplates` is additive metadata. `categoryId` retains its historical
eCommerce meaning; internal-category metadata is separate. The optional
`template_id` generation/context parameter distinguishes omission (saved choice)
from explicit false/null (Automatic); `templateId` participates in content-save
PATCH semantics. Model/source/revision metadata is not a publication flag.

The provider transport, selected AI models, SEO/GEO jobs, FAQs, image operations,
competitors, seven-item editorial checklist and optional ML observer are not
changed by this release. QAS ML reads/writes remain disabled and dry run enabled.

## Validation and deployment

Preserve the existing Odoo and QUnit suites. Test internal-category inheritance,
overrides, atomic saves, model lifecycle, administrator/company boundaries,
empty or invalid outputs, confirmed units and variant/Pack facts, stale responses
and draft preservation. Verify the selector/library and public description in
360/768/1024/1440px layouts, without external calls on navigation.

Before upgrade, capture exact package hashes and preserve server Git/remotes,
then back up the addon, database and filestore. Validate in an isolated QAS clone
before upgrading **only `bader_product_intelligence`**. Do not use `-u all`.
No production deployment, bulk generation or automatic publication is included.
